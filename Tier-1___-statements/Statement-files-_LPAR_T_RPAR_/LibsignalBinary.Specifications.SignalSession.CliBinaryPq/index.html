Whole-process correctness of the libsignal-cli ELF (PQXDH mode)

Trusted: the statement. Read it in full (see Computational/docs/TRUSTED_BASE.md). CliPqxdhBinaryCorrectPlaced bytes states that for every pair of placements (mpl, mmpl) linked at bytes (libsignalSessionLib.LinkedAt bytes mpl, VerifiedLibraries.mallocngLib.LinkedAt bytes mmpl), bytes parses as an ElfImage matching both libraries (Placed.CliElfCodeMatchesPlaced mpl mmpl elf), and for all hooks W : CliHooks and model extras X : UnreachedPqxdhPrimitives, the process Placed.cliRunPlacedSig mpl mmpl elf W (after Placed.cliTokenPatchPlaced, DEV-CLI10) is total except on .OutOfMemory (CliReachesOOMPlaced, DEV-CLI15) and satisfies CliSpecPqxdh (PqDir.lean) and CliSpecPqxdhNoMatch (PqDirNoMatch.lean, DEV-CLI11) at ⟨W.C, W.Q⟩.

Scope exclusions

  • keygen (PqDir.lean) and usage-error paths (CliRejectsMalformedCommandLine).

  • Party states outside PqxdhPartyInSpecDomain; init when a session already exists (DEV-C-PREV); non-canonical pre-key messages (DEV-CLI3); inputs of 2^32 bytes or more (2^32 - 2048 for a pre-key message's inner message).

  • After an accepted pre-key recv over a non-matching session: the written session file bytes and all subsequent calls on that directory (DEV-CLI11).

  • Outputs and files on runs that reach .OutOfMemory (DEV-CLI15).

  • CPUs with AES or PMULL, and SPQR's CPU probe (Placed.cliTokenPatchPlaced, DEV-CLI10).

Deviations of a run of the ELF

DEV-M6 (machine model): fixed stack, heap, and mmap layout. Each valid pair of multi-block placements mpl (libsignalSessionLib.LinkedAt bytes mpl) and mmpl (VerifiedLibraries.mallocngLib.LinkedAt bytes mmpl, Placed.CliElfCodeMatchesPlaced mpl mmpl elf) places code and data where elf maps them (for the pinned non-PIE ELF cliElfBytes, linked with stock ld.lld under cli-elf/stock.ld at load base 0x400000). The process gets an 8 MiB stack with its top at 0x7fff_ffff_0000 (DEV-CLI7), the engine's default auxiliary vector (AT_RANDOM = 16 zero bytes, AT_HWCAP = 0x3), mmap slots from 0x6000_0000_0000 (SignalSession/Process.lean), and brk starting at elf.brkStart. A real kernel places the stack, brk, and the mmap area at random addresses. Effect: out of scope: no claim for another stack/mmap/brk layout.

DEV-M7 (machine model): this ELF and its build. The closed headline claims are about the ELF pinned by SHA-256 in CliElf.lean (cliElfBytes): libsignal v0.105.4's libsignal-cli CLI built from source by scripts/cli-elf-stock --stdbin --build from third_party/libsignal/libsignal-session/cli-elf/stock/inputs_stock_stdbin.lock (rustc 1.98.1 and its aarch64-unknown-linux-musl self-contained/ CRT objects and libc.a, stock LLVM ld.lld 22.1.8 --no-relax under cli-elf/stock.ld, zig 0.16.0 for rdl_shim.S, std-main, and libsignal-session/translation.toml plus cli/io/translation.toml, with the software AES and SHA-2 backends). Effect: out of scope: production builds, other compilers and other flags are not covered.

DEV-M11 (machine model): each call is a fresh process. Each init / send / recv in Placed.cliRunPlacedSig mpl mmpl elf W runs from loadState (after Placed.cliTokenPatchPlaced) to exit_group or SIGABRT, with constant clock UNIX_EPOCH. Effect: out of scope for long-lived processes.

DEV-E1 (machine model): hooks write only their outputs. Under AAPCS64 a callee may clobber caller-saved registers (x0–x18, SIMD/FP, NZCV), whereas each hook in cliHookTablePlaced updates only its specified output registers/memory (cliBcmpHook writes x0; durationSinceExactHook writes its 24-byte result). Unhooked zero stubs halt and are forbidden by Placed.CliRunsToPlaced. Effect: w.l.o.g., argued for standard compiler code generation.

DEV-E7 (machine model): the ELF aborts where the model panics. Protocol-model panics map to aborted, and the ELF's panic symbols (isCliPanicSymbolPlaced) terminate the process with SIGABRT (abortOnPanic, CliProcess.lean). Effect: availability only; none on confidentiality or integrity.
