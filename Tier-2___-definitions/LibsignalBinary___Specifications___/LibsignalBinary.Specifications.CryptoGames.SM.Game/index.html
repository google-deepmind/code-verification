Secure messaging (SM): syntax and the two-way security game

Trusted in part. The theorems of Computational/Theorems/ use every definition in this file except Config.auth (the authenticity variant of Def. 10): read the others. Everything else here is checked by Lean. See Computational/docs/TRUSTED_BASE.md. structure SMSchemeL41–59 ↗#

ACD19 Def. 6: secure-messaging scheme with keys Key, party states St, messages Msg, sender coins Coins, and ciphertexts C.

DEV-SM16 (formalization): algorithms with explicit coins. ACD19 Def. 6 has randomized Send and a Rcv outputting (s', t, i, m) or ⊥. Here send takes explicit coins and receive returns Option, so Def. 7 (A) (rejection leaves state unchanged) holds by construction (DEV-SM4, DEV-SM17). The scheme also declares its skip window maxSkip (DEV-SM5).

structure SMScheme (Key St Msg Coins C : Type) where /-- `Init-A`: `A`'s initial state from the shared key. -/ initA : Key → St /-- `Init-B`: `B`'s initial state from the shared key. -/ initB : Key → St /-- `Send(s, m; r)`: encrypt `m` with coins `r`, returning the updated state and ciphertext. -/ send : St → Msg → Coins → St × C /-- `Rcv(s, c)`: returns `(s', t, i, m)` on acceptance, or `none` on rejection. -/ receive : St → C → Option (St × ℕ × ℕ × Msg) /-- Receiver skip window: correctness holds up to `maxSkip + 1` beyond the highest accepted index in the epoch (DEV-SM5). -/ maxSkip : ℕ

def safeChL191–192 ↗#

def safeCh (P : Party) : Bool := healedBy s.tL Δ (s.epoch P)

def safeInjL194–195 ↗#

def safeInj : Bool := healedBy s.tL Δ (min (s.epoch .A) (s.epoch .B))

def leakL197–203 ↗#

Record a leak at epoch l: updates tL ← max(tL, l) and prepends to leaks.

DEV-SM3 (formalization): tL only grows. ACD19 Fig. 2 assigns tL ← t_P + 1 in ep-mgmt and tL ← max(t_A, t_B) in corr-P; taking the maximum with the prior tL prevents an earlier-epoch leak after an accepted injection from lowering tL.

def leak (l : ℕ) : GameState St Msg C := { s with tL := some (maxOpt s.tL l), leaks := maxOpt s.tL l :: s.leaks }

def epMgmtL205–219 ↗#

ACD19 Fig. 2 ep-mgmt(P, bad): advances P into a new sending epoch when due (recording a leak if bad coins are used while unhealed) and resets idx P, refusing epochs above qep.

DEV-SM2 (formalization): epoch cap qep. qep is a game parameter: ep-mgmt refuses sending epochs > qep and inject rejects ciphertexts for epochs > qep + 1, keeping hybrid sums over t* ≤ qep + 1 finite (DEV-SM19).

def epMgmt (P : Party) (bad : Bool) : Option (GameState St Msg C) := if P.sendsIn (s.epoch P + 1) then if qep < s.epoch P + 1 then none else let s₁ := if bad && !(s.safeCh Δ P) then s.leak (s.epoch P + 1) else s some { s₁ with epoch := Function.update s₁.epoch P (s₁.epoch P + 1), idx := Function.update s₁.idx P 0 } else if qep < s.epoch P then none else some s

def recordL221–228 ↗#

ACD19 Fig. 2 record: updates P's state and index, adds r to trans, and marks r.pos in comp (if unhealed) and chall (if isChall).

def record (P : Party) (st' : St) (r : Record Msg C) (isChall : Bool) : GameState St Msg C := { s with st := Function.update s.st P st', idx := Function.update s.idx P r.pos.idx, trans := r :: s.trans, comp := if s.safeCh Δ P then s.comp else r.pos :: s.comp, chall := if isChall then r.pos :: s.chall else s.chall }

def delete (pos : Pos) : GameState St Msg C := { s with trans := s.trans.filter (fun r => r.pos != pos), chall := s.chall.filter (· != pos), comp := s.comp.filter (· != pos) }

def acceptL240–246 ↗#

State transition when P accepts a ciphertext at pos with new state st'.

def accept (P : Party) (st' : St) (pos : Pos) : GameState St Msg C := let s₁ := s.delete pos { s₁ with st := Function.update s₁.st P st', epoch := Function.update s₁.epoch P (max (s₁.epoch P) pos.epoch), maxAcc := fun Q t => if Q = P ∧ t = pos.epoch then max (s₁.maxAcc Q t) pos.idx else s₁.maxAcc Q t }

def trivialL248–255 ↗#

Whether pos is trivially forgeable: either in comp, or absent from trans with an epoch not yet healed at tL.

DEV-SM7 (formalization): position-based trivial forgeries. Because old receiving sessions are retained rather than erased via FS-Max/FS-Stop (DEV-SM11), positions not in transit from unhealed epochs (t < tL + Δ) are also treated as trivial forgeries.

def trivial (pos : Pos) : Bool := s.comp.contains pos || (!(s.trans.any (fun r => r.pos == pos)) && !(healedBy s.tL Δ pos.epoch))

def corrAllowedL257–266 ↗#

Whether corr-P is permitted: neither a challenge nor an uncompromised record from P.other is in transit.

DEV-SM6 (paper fix): corr-P waits for uncompromised records. ACD19 Fig. 2 blocks corr-P only while a challenge from P.other is in transit; here any uncompromised in-transit record from P.other also blocks corr-P, matching the FS-AEAD corruption rule needed for Thm 12 / Thm 5 (DEV-FS6; see Computational/Tests/Deviations/PaperCorrRule.lean).

def corrAllowed (P : Party) : Bool := !(s.chall.any (fun pos => pos.sender == P.other)) && !(s.trans.any (fun r => r.pos.sender == P.other && !(s.comp.contains r.pos)))

def afterCorrL268–274 ↗#

State update for corr-P: marks P.other's in-transit records compromised and records a leak at max(t_A, t_B).

def afterCorr (P : Party) : GameState St Msg C := let s₁ : GameState St Msg C := { s with comp := (s.trans.filter (fun r : Record Msg C => r.pos.sender == P.other)).map (fun r : Record Msg C => r.pos) ++ s.comp } { s₁.leak (max (s.epoch .A) (s.epoch .B)) with corrs := (P, s.epoch P) :: s.corrs }
end GameState
