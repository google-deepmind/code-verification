libsignal's double-ratchet session as a pure functional model

Trusted: definitions used by the statement. The theorems of Computational/Theorems/ use every definition in this file: read them. The theorems here are checked by Lean. See Computational/docs/TRUSTED_BASE.md.

Method-for-method pure functional transcription of a single libsignal v0.105.4 double-ratchet / triple-ratchet session (rust/protocol/src/{ratchet,double_ratchet,triple_ratchet,session_management,protocol}.rs, with wire and error types imported from LibsignalSignalMessage.lean). Inner &mut self methods run in Mut σ α := ExceptT SignalProtocolError (StateM σ) α (retaining partial mutations on error), while session-level tryDecryptFromRecord and messageEncrypt preserve the input record on error by operating on a clone (DEV-LS16); panics (overflow-checks = true, panic = "abort") surface as SignalProtocolError.panic (DEV-LS19).

Primitives (Crypto), protobuf encoding (SignalMessageProtoCodec, fixed to protoSignalCodec by the headline theorem, DEV-LS21), and SPQR (Spqr, an untrusted per-message HKDF salt source, DEV-LS24, DEV-LS25) are parameterized; X25519 is byte-level (X25519Fn, linked to an abstract group via X25519RealizesDh, DEV-LS29). Relative to ACD19 Fig. 9, libsignal initializes from PQXDH with Bob's signed pre-key (DEV-LS22, DEV-LS26), steps the DH ratchet eagerly on receive (DEV-LS1, DEV-LS2), derives message keys via chain HMAC plus salted HKDF (DEV-LS14), identifies epochs by ratchet key rather than epoch number with clear-text headers and 8-byte truncated MACs over identity keys and raw wire bytes (DEV-LS8, DEV-LS12, DEV-LS13, DEV-LS15, DEV-LS20, DEV-LS23), and bounds skipped keys and receiver chains (DEV-LS6, DEV-LS9, DEV-LS10, DEV-LS11, DEV-LS31).

DEV-LS28 (libsignal): scope of the model. Covers one non-self session (self_session = false, distinct identity keys) started from abstract initial keys: Sesame archived-session loops, PQXDH, PreKeySignalMessage wrapping, stores, identity trust checks, registration IDs, and the 30-day staleness check are out of scope here (LibsignalSessionApi.lean adds PreKeySignalMessage, stores, trust checks, and staleness for the public API). Session records use typed keys and Seed-form skipped keys, excluding malformed-protobuf InvalidSessionStructure branches.
