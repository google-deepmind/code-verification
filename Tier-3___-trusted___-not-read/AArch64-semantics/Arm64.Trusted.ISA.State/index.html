structure TimespecL172–213 ↗#

Per-call result of a Linux AArch64 clock_gettime syscall (struct __kernel_timespec in include/uapi/linux/time_types.h, written by put_timespec64 in kernel/time/time.c).

Per-call invariants guaranteed by the Linux kernel across all modeled clock IDs 0..7 (CLOCK_REALTIME = 0, CLOCK_MONOTONIC = 1, CLOCK_PROCESS_CPUTIME_ID = 2, CLOCK_THREAD_CPUTIME_ID = 3, CLOCK_MONOTONIC_RAW = 4, CLOCK_REALTIME_COARSE = 5, CLOCK_MONOTONIC_COARSE = 6, CLOCK_BOOTTIME = 7 in kernel/time/posix-timers.c and lib/vdso/gettimeofday.c):

  • Normalized nanoseconds (0 ≤ tv_nsec < 1_000_000_000, enforced by Fin 1000000000): high-resolution getters (ktime_get_real_ts64, ktime_get_ts64, ktime_get_raw_ts64 in kernel/time/timekeeping.c and vDSO do_hres in lib/vdso/gettimeofday.c) reduce nanoseconds via __iter_div_u64_rem(..., NSEC_PER_SEC, &ns); coarse getters (ktime_get_coarse_real_ts64, ktime_get_coarse_ts64 and vDSO do_coarse) and time-namespace offset additions (timens_add_monotonic, timens_add_boottime in include/linux/time_namespace.h) normalize via set_normalized_timespec64 (kernel/time/time.c), which adjusts tv_sec in both loops while (nsec >= NSEC_PER_SEC) and while (nsec < 0) so 0 ≤ tv_nsec < 1_000_000_000 even when tv_sec < 0; and CLOCK_BOOTTIME (ktime_get_boottime_ts64) and CPU clocks (posix_cpu_clock_get in kernel/time/posix-cpu-timers.c) convert s64 nanoseconds via ns_to_timespec64 (kernel/time/time.c), which likewise guarantees 0 ≤ tv_nsec < 1_000_000_000.

  • Seconds (sec : BitVec 64, unconstrained): CLOCK_REALTIME (0) and CLOCK_REALTIME_COARSE (5) cannot be set before the 1970 epoch (timespec64_valid in include/linux/time64.h rejects ts->tv_sec < 0, and timespec64_valid_settod is enforced by do_settimeofday64, timekeeping_inject_offset, and timekeeping_init in kernel/time/timekeeping.c, as well as do_sys_settimeofday64 in kernel/time/posix-stubs.c). In the initial time namespace (init_time_ns), all eight clocks 0..7 satisfy tv_sec ≥ 0. However, under CONFIG_TIME_NS (CLONE_NEWTIME), proc_timens_set_offset (kernel/time/namespace.c) validates a negative CLOCK_MONOTONIC offset against high-resolution ktime_get_ts64 (tp.tv_sec ≥ 0), whereas posix_get_monotonic_coarse (CLOCK_MONOTONIC_COARSE = 6) and posix_get_monotonic_raw (CLOCK_MONOTONIC_RAW = 4) apply that same ns->offsets.monotonic via timens_add_monotonic (kernel/time/posix-timers.c, lib/vdso/gettimeofday.c): because ktime_get_coarse_ts64 omits the sub-tick timekeeping_get_ns(&tk->tkr_mono) delta and ktime_get_raw_ts64 omits NTP slewing, timens_add_monotonic can normalize tv_sec to a negative value (e.g. -1) while keeping 0 ≤ tv_nsec < 1_000_000_000. Moreover, even for single calls, CLOCK_REALTIME can jump backward across calls (clock_settime / adjtimex). Leaving sec : BitVec 64 unconstrained with nsec : Fin 1000000000 therefore captures the exact per-call invariant guaranteed across all clocks 0..7.

structure Timespec where sec : BitVec 64 := 0#64 nsec : Fin 1000000000 := ⟨0, Nat.zero_lt_succ _⟩ deriving DecidableEq, Repr, Inhabited, BEq

structure OracleL215–251 ↗#

Results of the nondeterministic system calls. Query n is the n-th nondeterministic syscall of the run, counting from zero (State.oracleIdx).

Step stays deterministic. The nondeterminism comes from the initial state: specs such as subroutine_ok quantify over every entry state s0, so they hold for every s0.oracle, i.e. for every possible kernel behaviour. Indexing by the query count loses nothing: given s0, the whole history before query n is determined, so a kernel that looks at that history (including the clock ID passed to clock_gettime) is still just some function of n.

  • mmap n: preferred address candidate for the n-th query if it is an anonymous mmap or mremap(..., MREMAP_MAYMOVE). execMmap and execMremap sanitize the candidate (mm/mmap.c get_unmapped_area): if it is below MMAP_MIN_ADDR, not page-aligned, exceeds the 48-bit user virtual address space (2 ^ 48), or overlaps an already-mapped byte, they deterministically substitute the lowest free page-aligned gap in [MMAP_MIN_ADDR, 2 ^ 48) that fits, failing only when no free gap of the requested size exists,

  • mremapFail n: whether the n-th query refuses an mremap(..., MREMAP_MAYMOVE) with -ENOMEM (leaving the existing mapping intact), conservatively retained to over-approximate nondeterministic mremap refusal (e.g. RLIMIT_AS / vm.max_map_count or allocator fallback paths from mremap to mmap),

  • getrandom n i: byte i of the buffer filled by the n-th query if it is a getrandom,

  • clockGettime n: normalized struct timespec (0 ≤ nsec < 1_000_000_000) written by the n-th query if it is a successful clock_gettime, with no monotonicity relation between successive queries,

  • exclFails: finite schedule of spurious store-exclusive (STXR*/STLXR*/STXP/STLXP) failures copied into State.exclFails at process load time (ElfImage.loadState). Every execution has finitely many spurious failures, adversarially placed (headD false, consumed per non-faulting store-exclusive). This models eventual LL/SC progress without an exclusive monitor; a retry-less stxr is unprovable because exclFails = [true] is a valid initial state.

structure Oracle where mmap : Nat → BitVec 64 := fun _ => 0#64 mremapFail : Nat → Bool := fun _ => false getrandom : Nat → Nat → BitVec 8 := fun _ _ => 0#8 clockGettime : Nat → Timespec := fun _ => {} exclFails : List Bool := []
